# G-Patrol System Summary & Development History

เอกสารฉบับนี้สรุปโครงสร้างฐานข้อมูล เงื่อนไขของระบบ และตัวแปรสำคัญทั้งหมดของระบบเดินตรวจ (G-Patrol) จากการปรับปรุงอัปเดตล่าสุด ณ วันที่ 16 กรกฎาคม 2569 เพื่อให้ง่ายต่อการเก็บรักษาเป็นประวัติหรือนำไปวางในบราวเซอร์สำหรับการพัฒนาต่อยอดในอนาคต

---

## 1. โครงสร้างฐานข้อมูล (Database Structure - Supabase Schema: `g_patrol`)
ในการเชื่อมต่อฐานข้อมูล Supabase API ระบบปัจจุบันจะวิ่งผ่าน Custom Schema ชื่อ `g_patrol` (โดยฝั่งสคริปต์หน้าบ้านกำหนด Option การเชื่อมต่อเป็น `{ db: { schema: 'g_patrol' } }` ใน Supabase Client) ประกอบด้วยตารางหลักดังนี้:

*   **ตาราง `g_patrol.g_patrol_users`**: เก็บข้อมูลผู้ใช้งาน
    *   `id` (UUID - Primary Key)
    *   `username` (Text)
    *   `password` (Text)
    *   `display_name` (Text)
    *   `role` (Text): ได้แก่ `admin`, `court marshal`, `guard` (โซนบริเวณศาล), `guard2` (โซนบ้านพัก)
*   **ตาราง `g_patrol.g_patrol_checkpoints`**: เก็บข้อมูลจุดตรวจเช็คอิน (CP-01 ถึง CP-25)
    *   `id` (UUID - Primary Key)
    *   `name` (Text): ชื่อจุดตรวจ
    *   `asset_number` (Text): รหัสจุดตรวจ เช่น CP-01
    *   `location` (Text): บริเวณที่ตั้ง เช่น บริเวณศาล หรือ บ้านพัก
*   **ตาราง `g_patrol.g_patrol_audit_records`**: บันทึกการเดินตรวจสแกนจริง
    *   `id` (UUID - Primary Key)
    *   `asset_id` (UUID REFERENCES checkpoints)
    *   `status` (Text): สถานะการตรวจ (`normal` (ปกติ), `damaged` (พบสิ่งผิดปกติ), `lost` (เกิดเหตุเร่งด่วน))
    *   `notes` (Text): รายละเอียดหมายเหตุเหตุการณ์ไม่ปกติที่ยามพิมพ์รายงานเข้ามา
    *   `fiscal_year` (Integer): ปีงบประมาณ (เช่น 2569)
    *   `audited_by` (UUID REFERENCES users): เจ้าหน้าที่ผู้ทำการสแกนตรวจ
    *   `audited_at` (TIMESTAMP WITH TIME ZONE): วันเวลาจริงที่กดสแกนส่งข้อมูล (เก็บแบบ UTC)
    *   `image_url` (Text): ลิงก์เก็บรูปภาพถ่ายสภาพจริงของจุดตรวจขณะสแกน
    *   `latitude` (Double Precision) & `longitude` (Double Precision): พิกัด GPS ณ วินาทีที่สแกนสำเร็จ

## 2. เงื่อนไขและกฎเกณฑ์การทำธุรกิจ (System Rules & Shift Boundaries)
*   **กะเวลาตรวจแบบใหม่ 8 กะ (ต่อเนื่อง 24 ชม.)**: ระบบใช้ตารางกะเวลาใหม่ในการแยกแยะประวัติและเคลียร์ข้อมูล โดยคำนวณครอบคลุมช่วงเวลาพัก (Gap) ท้องถิ่นเพื่อป้องกันข้อผิดพลาดเวลาเครื่องสแกนล่าช้าดังนี้:
    1.  **กะที่ 1**: 06:00 - 11:00 น. *(ครอบคลุมช่วงเวลาสแกนจริง 06:00 - 11:29 น.)*
    2.  **กะที่ 2**: 12:00 - 14:00 น. *(ครอบคลุมช่วงเวลาสแกนจริง 11:30 - 14:14 น.)*
    3.  **กะที่ 3**: 14:30 - 16:00 น. *(ครอบคลุมช่วงเวลาสแกนจริง 14:15 - 16:14 น.)*
    4.  **กะที่ 4**: 16:30 - 18:00 น. *(ครอบคลุมช่วงเวลาสแกนจริง 16:15 - 19:14 น.)*
    5.  **กะที่ 5**: 20:30 - 22:00 น. *(ครอบคลุมช่วงเวลาสแกนจริง 19:15 - 00:29 น. ของวันถัดไป - รองรับข้ามคืน)*
    6.  **กะที่ 6**: 00:30 - 02:00 น. *(ครอบคลุมช่วงเวลาสแกนจริง 00:30 - 02:14 น.)*
    7.  **กะที่ 7**: 02:30 - 04:00 น. *(ครอบคลุมช่วงเวลาสแกนจริง 02:15 - 04:14 น.)*
    8.  **กะที่ 8**: 04:30 - 06:00 น. *(ครอบคลุมช่วงเวลาสแกนจริง 04:15 - 05:59 น.)*
*   **การเคลียร์ล้างหน้าจอและภาพตัวอย่างเมื่อขึ้นกะใหม่ (Auto Reset)**: เมื่อเวลามือถือขยับขึ้นกะถัดไป หน้าตารางเช็คอินจะเคลียร์สถานะทั้งหมดกลับเป็น "ยังไม่ได้ตรวจ" สีเทา และภาพถ่ายพรีวิวจุดสแกนของกะก่อนหน้าจะถูกซ่อนกลายเป็น "ไม่มีภาพ" เพื่อให้พร้อมสำหรับเริ่มกะใหม่โดยอัตโนมัติ
*   **ระบบป้องกันการสแกนซ้ำ (Duplicate Protection)**: เจ้าหน้าที่จะสแกนเช็คอินจุดตรวจใดจุดตรวจหนึ่งซ้ำอีกไม่ได้ภายในรอบกะช่วงเวลาปัจจุบัน
*   **การแบ่งสิทธิ์จำกัดขอบเขตการสแกนของยาม (Role-Based Constraints)**:
    *   `guard` (ยามบริเวณศาล): ล็อกอินแล้วจะถูกบังคับให้อยู่ในหน้าจุดตรวจ และจะเห็น/สแกนได้เฉพาะโซน "บริเวณศาล" เท่านั้น แถบนำทางด้านล่างจะถูกปิดซ่อน
    *   `guard2` (ยามบ้านพัก): ล็อกอินแล้วจะถูกบังคับให้อยู่ในหน้าจุดตรวจ และจะเห็น/สแกนได้เฉพาะโซน "บ้านพัก" เท่านั้น แถบนำทางด้านล่างจะถูกปิดซ่อน
    *   `court marshal` & `admin`: เห็นจุดตรวจทุกโซน มีหน้าแผงสรุปยอด Dashboard รวมถึงแถบนำทางเครื่องมือครบครัน สิทธิ์ในการเลือกกำหนดวันเวลารายงานเช็คอินและสั่งส่งออกรายงาน PDF / Excel ได้

## 3. ตัวแปรและฟังก์ชันสำคัญ (ใน `app.js` และสคริปต์หน้าบ้าน)
*   **`getShiftTimeRange(dateObj)`**: ฟังก์ชันหลักในการนำเวลาปัจจุบันแปลงเป็นกะ `shift1` - `shift8` และสร้างช่วงวันเวลา `startIso` และ `endIso` เพื่อใช้ส่งต่อให้กับ API ฐานข้อมูลอย่างแม่นยำ ป้องกันบั๊กการประมวลผลสตริงเขตเวลาคลาดเคลื่อนบน iOS Safari โดยแปลงผ่านพารามิเตอร์แบบตัวเลขตรงตัว (`new Date(y, m, d, h, min, s)`)
*   **`getLogShift(date)`**: คืนค่า String กะปฏิบัติงาน ณ เวลาในพารามิเตอร์ (`shift1` ถึง `shift8`)
*   **`shiftTextMapping`**: คีย์แมปชื่อแสดงผลภาษาไทยของแต่ละกะ
*   **`requestGPSLocation()`**: ฟังก์ชันขอสิทธิ์การเข้าถึง Geolocation บนอุปกรณ์สมาร์ตโฟนเพื่อดึง ละติจูด/ลองจิจูด และนำมาเก็บในฟิลด์ซ่อนส่งไปพร้อมกับแบบฟอร์มบันทึกเช็คอินสแกน
*   **การแสดงพิกัด GPS และ เหตุการณ์ไม่ปกติ**:
    *   ในหน้าตารางจุดตรวจ (`view-checkpoints`) และตารางแดชบอร์ดหลัก (`view-dashboard`) ของแอดมิน: ระบบจะแสดงป้ายปุ่ม **`ดูพิกัดแผนที่ (GPS)`** นำทางเข้า Google Maps และแสดงแถบเตือนสีแดง **`⚠️ รายละเอียดเหตุการณ์ไม่ปกติ: [ข้อความเหตุการณ์]`** คู่อยู่กับข้อมูลผู้รายงานแบบเรียลไทม์

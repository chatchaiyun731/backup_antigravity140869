# แผนการพัฒนาระบบลงชื่อเข้าใช้ (Login System) และการแบ่งสิทธิ์ผู้ใช้งาน

การเพิ่มระบบ Login ถือเป็นการยกระดับแอปพลิเคชันให้มีความปลอดภัยและใช้งานได้จริงมากขึ้น โดยเราจะใช้ Google Sheets เป็นฐานข้อมูลเก็บรายชื่อผู้ใช้งาน รหัสผ่าน รูปโปรไฟล์ และสิทธิ์การใช้งาน (Role) 

## ⚠️ User Review Required (ส่วนที่ต้องการการยืนยันจากคุณ)

เนื่องจากระบบ PWA ที่โฮสต์บน Cloudflare Pages เป็นแบบ Static (ไม่มีเซิร์ฟเวอร์ Database ของตัวเอง) การทำระบบ Login โดยใช้ Google Sheets จะเป็นการตรวจสอบข้อมูลแบบเบื้องต้น (Basic Authentication) ซึ่งเพียงพอและเหมาะสมสำหรับ **การใช้งานภายในองค์กร** แต่ไม่ได้มีความปลอดภัยขั้นสูงสุดระดับธนาคาร (เช่น ไม่มีระบบ Token เข้ารหัสซับซ้อน) 

## ❓ Open Questions (คำถามเพื่อความชัดเจนก่อนเริ่มงาน)

1. **รูปแบบการ Login:** สำหรับ รปภ. คุณต้องการให้ใช้ **"รหัสพนักงาน (Employee ID) + รหัสผ่าน/PIN 4 ตัว"** หรือใช้ **"ชื่อผู้ใช้ (Username) + รหัสผ่าน"** ครับ? (โดยทั่วไป รปภ. มักจะถนัดใช้ รหัสพนักงาน + PIN สั้นๆ ครับ)
2. **หน้าจอหลัง Login ของระดับบริหาร:** ถ้าระดับ **Court Marshal** หรือ **Admin** ล็อกอินเข้ามา คุณต้องการให้แอปแสดงผลหน้าจอแบบไหนครับ? (เช่น ให้แสดงปุ่มกดไปดูรายงานใน Looker Studio หรือแสดงข้อความต้อนรับธรรมดา เพราะ Court Marshal ไม่ต้องกดเช็คอินจุดตรวจ)

## 🛠️ Proposed Changes (รายละเอียดการแก้ไขระบบ)

### 1. ฝั่งฐานข้อมูล (Google Sheets)
#### [NEW] สร้างแผ่นงาน (Sheet) ใหม่ชื่อ `Users`
เราจะสร้างตารางเก็บข้อมูลผู้ใช้ โดยมีคอลัมน์ดังนี้:
* `Username` (หรือ รหัสพนักงาน)
* `Password` (รหัสผ่าน หรือ PIN)
* `Name` (ชื่อ-สกุล)
* `Role` (สิทธิ์: `Guard`, `Court Marshal`, `Admin`)
* `ProfilePic` (ลิงก์รูปภาพโปรไฟล์)

### 2. ฝั่ง Backend (Google Apps Script)
#### [MODIFY] โค้ด Apps Script (API)
* เพิ่มระบบตรวจสอบ (Authentication): เมื่อ Frontend ส่ง Username และ Password เข้ามา API จะไปค้นหาใน Sheet `Users`
* หากเจอและรหัสผ่านถูกต้อง: จะส่งข้อมูล Name, Role, ProfilePic กลับไปให้ Frontend
* หากไม่เจอ: ส่งสถานะ Error กลับไป

### 3. ฝั่ง Frontend (PWA บน Cloudflare Pages)
#### [MODIFY] `index.html` (เปลี่ยนเป็นหน้า Login / Dashboard)
* **หน้า Login (ด่านแรก):** ช่องกรอก Username และ Password
* **ระบบจดจำผู้ใช้:** ใช้ `localStorage` ในเบราว์เซอร์ เพื่อให้ รปภ. ไม่ต้องพิมพ์รหัสใหม่ทุกวัน (ล็อกอินครั้งเดียวอยู่ได้ยาวๆ)
* **หน้า Dashboard (ด่านสอง):** 
  * แสดง **รูปโปรไฟล์** และ **ชื่อผู้ใช้งาน** ที่มุมบนของแอป
  * **ระบบ Role-based Routing:** 
    * ถ้า Role = `Guard` -> แสดงหน้าฟอร์มกรอกข้อมูลจุดตรวจ
    * ถ้า Role = `Court Marshal` / `Admin` -> แสดงหน้าจอต้อนรับสำหรับผู้บริหาร พร้อมลิงก์ไปดูรายงาน

## 🧪 Verification Plan (แผนการทดสอบ)

### Manual Verification
1. เพิ่มข้อมูลจำลอง (Mock Data) ของผู้ใช้ทั้ง 3 ระดับ (Guard, Court Marshal, Admin) ใน Google Sheets
2. ทดสอบล็อกอินด้วยรหัสของ Guard -> ต้องเห็นหน้าส่งรายงาน และมีรูปโปรไฟล์ตัวเองขึ้น
3. ทดสอบล็อกอินด้วยรหัสของ Court Marshal -> ต้องเห็นหน้าจอสำหรับหัวหน้า (ไม่เห็นฟอร์มจุดตรวจ)
4. ทดสอบใส่รหัสผิด -> ต้องแจ้งเตือนว่ารหัสผ่านไม่ถูกต้อง
